# Как сравнить модели команды

## Если у коллеги уже есть модель

Нужен совместимый GGML-файл Whisper Small. Запишите, из какой FP16 его получили, каким методом и на каких данных калибровали, и сохраните SHA-256. Положите файл под новым именем, например `.work/models/team_gptq.bin`. После [подготовки окружения и аудио](../README.md#для-команды) проверьте загрузку на двух записях и выполните пробный замер.

```sh
uv run research/benchmark.py smoke team_gptq+ctx768 --backend cpu --repeats 1 --output .work/team-smoke
uv run research/tune_target.py --backend cpu --out .work/team-gptq-pilot \
  --models fp16 q4_0 m3_enc1 team_gptq --contexts full 768 --threads 4 \
  --budget-pp 1 --repeats 1 --confirm test
```

## Если объединяем способы квантизации

Возьмите [карту m3_enc1](../policies/m3_enc1.json). Коллега передаёт алгоритм упаковки весов и статистики, собранные на train. В [экспортёре](../scripts/export_model.py) метод нужно разрешить в `resolve_policy` и вызвать в `export`. Каждый тензор квантуем один раз из исходного FP16. Загрузчик уже поддерживает блоки GGML Q4_0, Q5_0 и Q8_0. [Контракт форматов](runtime.md)

Чтобы измерить вклад метода коллеги, сравните новый checkpoint с `m3_enc1` при тех же типах матриц, окне и потоках. Чтобы измерить вклад окна, меняйте только `--contexts`. `q4_0` — равномерная Q4, `m3_enc1` — смешанная Q4/Q8.

## Общий замер

1. Подготовьте [расширенное аудио](../data/README.md). Договоритесь о списке моделей, числе повторов, потоках и допустимом росте WER отдельно для RU и EN.
2. Повторите команду подбора на общем устройстве с новым каталогом `--out`, флагами `--dev m3_dev --confirm m3_test` и согласованным числом повторов. Выбор делает dev. На test скрипт запускает зафиксированных победителей и FP16 того же устройства.
3. Для таблицы команды возьмите SHA-256 и параметры из `profile.json`, выбор по бюджету из `selection.json`, WER и RTF из `confirmation-m3_test.json`. Полная выборка содержит 1 891 запись RU и 948 EN. Панель из 32 + 32 входит в этот тест и годится для проверки разброса времени.

Для отдельного сравнения **всех** моделей при одном окне можно начать с панели из 32 + 32 записей. В `m3_panel-summary.csv` появятся строки RU и EN для каждой модели, в том числе для тех, которые вышли за бюджет WER.

```sh
uv run research/benchmark.py m3_panel q4_0+ctx768 m3_enc1+ctx768 team_gptq+ctx768 \
  --backend cpu --threads 4 --repeats 1 --output .work/team-panel/raw
uv run research/analyze.py m3_panel --raw .work/team-panel/raw --out .work/team-panel --summary-only
```

В конце [презентации](../results/whisper-small.pptx) есть две редактируемые таблицы. Для сравнения методов перенесите RU/EN WER и RTF из строк RTN, GPTQ и калибровки при одной карте, окне и устройстве. Для сравнения устройств используйте результаты на одной тестовой выборке: RTF двух контролей (FP16 с полным окном и Q4 с окном от 768), затем конфигурацию победителя, её ускорение к FP16 и WER обоих языков. Если Q4 отсутствует среди подтверждённых победителей, измерьте её тем же бенчмарком.
