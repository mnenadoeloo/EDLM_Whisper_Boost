# Проверка карты для Apple M3 Pro

Протокол фиксирует выбор до распознавания расширенного test. Исходная карта — `enc_attn`. Все сравнения на новых данных используют один и тот же whisper.cpp CPU, 4 потока, greedy, язык из корпуса, минимум контекста 768 и одинаковое окно на каждой паре. Окно вычисляется как min(1500, max(768, 64 × ceil((секунды + 1) × 50 / 64))). Для записей длиннее окна действует обычная обработка whisper.cpp.

## Данные и порядок

- Новые dev — 32 записи Golos farfield validation и 32 LibriSpeech dev-clean. Старые идентификаторы, исходные и приведённые WAV-дубликаты исключаются. Для EN также исключаются дикторы, уже участвовавшие в пилоте.
- Подтверждение — все 1 891 размеченные записи Golos farfield test, оставшиеся после пилота (у строки 848 отсутствует эталон) и 948 записей LibriSpeech test-clean от 16 новых дикторов. Манифест и случайная подвыборка по 32 записи каждого языка для повторных замеров фиксируются до dev-инференса. Для RU сведений о дикторах нет.
- На dev один прогон каждой карты, включая FP16 и uniform Q4 при том же окне. На расширенном тесте один парный прогон на запись. На подвыборке отдельно три парных прогона. Перед серией прогревается каждый вариант на отдельном smoke-примере. На тесте порядок записей перемешивается, модели запускаются подряд, первый участник пары чередуется внутри языка и меняется в следующем повторе.
- Скорость — отношение суммарных секунд CLI к суммарным секундам аудио (RTF), включая запуск и загрузку. Ускорение — RTF исходной карты / RTF новой. WER — суммарное редакционное расстояние по словам / число эталонных слов, та же нормализация, что в пилоте. Для разницы WER и отношения скоростей рассчитываются 95%-е парные процентильные bootstrap-интервалы, 2 000 выборок. Единица — диктор EN или запись RU.

## От профиля до одной карты

1. Замерить штатный GGML mul_mat при фактическом размещении весов из загруженных Q4_0, Q5_0 и Q8_0 моделей. Четыре потока, по два прогрева и семь измерений на точку в каждом из трёх проходов (блоки 0, 5 и 11, порядок форматов циклически меняется). Вокабулярная проекция общая для всех блоков. Сохранить форму, тип буфера и время. Число декодирующих шагов оценить на восьми train-записях.
2. По результатам пилотной чувствительности изменять Q/K/V/out encoder self-attention и decoder cross-attention, отдельно рассмотреть Q5 для общей embedding/output матрицы. Одно назначение на все 12 слоёв каждой семьи. Для остальных подходящих матриц зафиксировать Q4. Ограничить дополнительный объём весов бюджетом исходной карты. Выбрать по одной самой дешёвой комбинации для 0/25/50/75/100% исходного бюджета в энкодере и одну с Q5 в выходной проекции. Допуск по недоиспользованию бюджета для последней меньше 0,844 MiB.
3. Цена изменяемых проекций — сумма медиан по 21 замеру. Для матриц с аудиопозициями взять N=768, для токеновых — один N=4 и среднее число N=1. Умножить на число матриц данной роли. Это оценка части графа, поэтому основная метрика скорости измеряется отдельно на полном распознавании. Эквивалентные по стоимости перестановки разрешаются в фиксированном порядке.
4. Для новой карты требовать на dev WER не выше чем на 1 п.п. относительно каждого из двух контролей (FP16 и исходная карта), отдельно для обоих языков. Среди новых карт, прошедших фильтр, выбрать минимальную профильную стоимость. Если ни одна не проходит, взять карту с минимальным худшим превышением, затем с минимальной стоимостью, явно отметить неуспех dev. Карты из пилота участвуют как контроли. Зафиксировать единственного кандидата, контроль и хеши до запуска test. Вывод о скорости и качестве делать по расширенному тесту.
